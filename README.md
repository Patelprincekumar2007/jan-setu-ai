## 1. Prototype Scope & Transparency Notice

NagrikLens AI is an institutional decision-support prototype built to demonstrate how citizen development requests can be consolidated, structured with Google Gemini, grounded against verified open public datasets, and triaged using transparent deterministic prioritization algorithms.

**Important Disclosures:**
- NagrikLens AI is an AI decision-support prototype.
- It is NOT an official government portal, grievance redressal system, or government-endorsed application.
- It does NOT claim official government affiliation, deployment, or partnership.
- Priority scores and hotspot groupings are deterministic decision-support heuristics, not statutory government ratings or predictions.

---

## 2. Core Information Separation Architecture

The platform strictly separates three classes of information:
1. **Citizen Data:** Unverified issues and requests submitted directly by citizens.
2. **Public Source Data:** Verified open data from official repositories (e.g. data.gov.in, Ministry of Jal Shakti) published under the Government Open Data License - India (GODL).
3. **AI Interpretation:** Structured parameters, grounded summaries, and observations generated by Google Gemini models.

Public data is never presented as citizen submissions, and AI inferences are never presented as official government data.

## 4. Key Platform Features (Stages 3A through 3J)

### 4.1 Multi-Sector Public Data Foundation (Stage 3D)
- Ingestion of 100 verified public data records across 4 civic categories:
  - **Water Supply:** Jal Jeevan Mission (JJM 2024 Baseline)
  - **Healthcare:** National Health Mission (NHM 2024 Sub-Centre Facility Index)
  - **Sanitation:** Swachh Bharat Mission - Gramin (SBM-G 2024 Toilet Coverage)
  - **Roads / Connectivity:** Pradhan Mantri Gram Sadak Yojana (PMGSY Habitation Connectivity)
- Strict provenance metadata: Publisher, portal URL, license (GODL), geographic level, temporal anchor.

### 4.2 Semantic & Hybrid Retrieval Engine (Stage 3C)
- FAISS IndexFlatIP vector store over L2-normalized 384-dimensional multilingual embeddings (`paraphrase-multilingual-MiniLM-L12-v2`).
- 3-tier metadata match level ranking combined with vector cosine similarity.
- Deterministic canonical deduplication and tie-breaking.

### 4.3 Evidence-Grounded RAG (Stage 3C-4)
- Google Gemini 2.5 Flash / Pro integration with prompt injection defenses.
- Isolated citizen context tags `<citizen_submission>`.
- Mandatory citation requirement (e.g. `EVID-...`) and explicit evidence gap reporting.

### 4.4 Deterministic Prioritisation Engine (Stage 3E: `priority-v1`)
- Mathematical evaluation using 5 transparent factors:
  1. Reported Severity (30%)
  2. Affected Households (25%)
  3. Infrastructure Deficit (25%)
  4. Vulnerability Evidence (10%)
  5. Geographic Evidence Coverage (10%)
- Dynamic weight re-normalization when certain metrics are unavailable.

### 4.5 Deterministic Demand Hotspots (Stage 3F: `hotspot-v1`)
- Demand clusters calculated strictly from actual stored `CitizenRequest` records.
- Zero fabricated mock demand, zero unconstrained ML clustering.

### 4.6 Executive Decision-Support Dashboard (Stage 3G)
- 8 live, verified telemetry panels: Overview KPIs, Category Breakdown, Geographic Demand, Evidence Coverage, Severity Distribution, Hotspot Registry, Datasets Catalog, Request Drilldown.
- Honest zero-state representations and institutional palette.

### 4.7 Reusable Request Analytics APIs (Stage 3H)
- Dedicated analytical endpoints for categories, geography, timeline, evidence-coverage, and severity distributions.

### 4.8 Multilingual & Voice Intake (Stage 3I)
- Support for English, Hindi (`hi`), and Gujarati (`gu`) with full original text preservation.
- Secure audio transcription endpoint (`POST /api/voice/transcribe`) with honest 503 fallback when speech credentials are unconfigured.

### 4.9 Production Security Hardening (Stage 3J)
- `SecurityHeadersMiddleware`: HTTP security headers (`X-Content-Type-Options`, `X-Frame-Options`, `X-XSS-Protection`, `Referrer-Policy`).
- `RateLimitMiddleware`: 60 requests/min compute protection.
- Explicit CORS origin allowlist.
- Global sanitized exception handling preventing stack trace leakage.

### 4.10 Production Deployment Preparation (Stage 3K)
- **Container Architecture:** Linux-compatible `python:3.11-slim` backend container and multi-stage `node:20-alpine` + `nginx:alpine` frontend container.
- **Cloud Run Readiness:** Configurable `PORT` binding (defaults to 8080), non-root execution, dual lightweight `/health` & `/api/v1/health` probes.
- **SPA Fallback Routing:** Nginx configured with `try_files $uri $uri/ /index.html;` ensuring direct navigation to all routes (`/`, `/submit`, `/track`, `/dashboard`, `/datasets`, `/privacy-policy`, `/terms`).

## 6. Setup & Execution

### Prerequisites
- Python 3.11+
- Node.js 18+

### Backend Setup
```bash
cd backend
python -m venv venv
source venv/bin/activate  # Or `venv\Scripts\activate` on Windows
pip install -r requirements.txt
cp .env.example .env
uvicorn main:app --host 127.0.0.1 --port 8000
```

### Frontend Setup
```bash
cd frontend
npm install
npm run dev
```

### Docker Integration (Local Testing)
```bash
docker compose up --build
```
